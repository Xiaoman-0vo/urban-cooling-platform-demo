# 04 · 采集适配器说明（微博实时数据的可行路径）

> 本文回答一个问题：**我们的 agent 能不能自己上微博看帖子、看评论，然后给出结果？**
> 结论：能，但**必须带一个登录态 Cookie**。匿名访问已经被微博关掉了。本文记录实测证据、Cookie 获取步骤、限速与合规底线，以及采集器的节点编排。

---

## 1. 实测结论（本机验证，不是推测）

登录凭证：`scripts/refresh-cookie.ps1`（从 Edge 直接取，见 docs/03）；连通性探针：`scripts/probe-weibo.ps1`

| 检查项 | HTTP | 结果 | 说明 |
|---|---|---|---|
| 热搜榜 `weibo.com/ajax/side/hotSearch` | 200 | ✅ 可用 | 匿名返回 **52 条**热词（含热度、标签），不需要 Cookie |
| 关键词搜索 `m.weibo.cn/api/container/getIndex` | 200 | ❌ 需登录 | 返回 `{"ok":-100, "url":".../sso/signin..."}` → 跳转登录 |
| 一级评论 `m.weibo.cn/api/comments/show` | — | 未测 | 拿不到微博 id（上一步失败），无法测 |

两个**踩过的坑**（已固化进脚本，别再踩）：

1. **必须用 `curl.exe`，不能用 `Invoke-WebRequest`**。Windows PowerShell 5.1 会做证书吊销检查，经系统代理时必报
   `CRYPT_E_REVOCATION_OFFLINE (0x80092013)`，连接直接断。curl 加 `--ssl-no-revoke` 可绕过。
2. **UA 必须与端点匹配**。`weibo.com` 的 PC 接口只认**桌面 UA**；`m.weibo.cn` 的移动端接口只认**移动 UA**。
   混用直接 **403**（我第一次就是这么失败的）。

还有两个状态码要认识：

| 码 | 含义 | 处理 |
|---|---|---|
| `403` | 缺 Cookie，或 UA/Referer 不匹配 | 检查 Cookie 与 UA |
| `432` | 微博风控：Cookie 失效 / 请求太频 | 停止，等 10 分钟，降低频率 |
| `ok:-100` | 没登录 | Cookie 过期，重新取 |

## 2. 拿 Cookie（5 步，约 2 分钟）

> ⚠️ **Cookie 等同于你的登录凭证**，别人拿到就能以你的身份操作微博。所以：
> 只存在本机 `.weibo-cookie` 文件里（已写进 `.gitignore`，不会进 git、不会被截图进文档）；
> 不要发到群里、不要贴进聊天记录；**比赛结束后**去 微博 → 设置 → 账号与安全 → 退出所有设备，即可让它立即失效。

1. 打开 **Edge 或 Chrome**，访问 <https://m.weibo.cn>，**登录**你的微博账号（手机上扫码即可）。
2. 按 `F12` 打开开发者工具 → 切到 **网络 / Network** 面板。
3. 按 `F5` 刷新页面，在左侧请求列表里点**第一条**（通常是 `m.weibo.cn` 本身）。
4. 右侧找到 **请求头 / Request Headers**，找到 `Cookie:` 这一行，**选中整行值**（一长串，形如 `SUB=_2A25...; SUBP=0033Wr...; _T_WM=...`），复制。
5. 在项目根目录新建文件 **`.weibo-cookie`**（注意前面有个点，没有扩展名），把 Cookie 值粘进去，**保存为 UTF-8**，不要加引号、不要换行。

存好后自检：

```powershell
cd "C:\Users\26864\Desktop\华为ICT大赛\weibo-demand-agent"
powershell -NoProfile -ExecutionPolicy Bypass -File scripts\probe-weibo.ps1
```

三项应全部变成 `OK`。若第 2 项仍失败，多半是 Cookie 复制不全（只复制了一半）或已过期。

## 3. 合规与限速（写进代码，不靠自觉）

| 约束 | 做法 |
|---|---|
| 只采公开内容 | 只抓公开微博正文与评论，**不碰**私信、好友圈、仅自己可见内容 |
| 不存身份信息 | 落库只保留 `content_hash` 与去标识后的文本；**不存** 昵称、头像、主页链接、uid 明文 |
| 小样本 | 单次运行上限 **30 条微博 / 每博 1 页评论**，够演示，不构成规模化抓取 |
| 限速 | 每次请求间隔 **3 秒**，串行不并发 |
| 不用他人账号 | 只用你自己/团队成员的账号，且明知风险 |
| 可随时关停 | 采集器有 `enabled` 开关，关掉后整条链退回 mock 数据 |

风险要说清楚：**用自己账号跑抓取有被限流甚至临时封号的可能**。所以默认参数很小、间隔很大，演示前先跑一次确认，别在答辩现场现抓。

## 4. 采集器节点编排（W1）

> 设计原则：**采集失败不能拖垮分析**。所以 W1 只负责「把微博变成 `posts[]`」，分析仍由 `03-demand-agent-api` 的 `extract_batch` 完成。

```
定时触发 (Schedule, 每 6 小时)
  → 1-配置读取 (Code: 读 data/monitor_config.json，取关键词与开关)
  → IF 采集开关关闭 → 走 mock → 合并
  → 2-搜索请求 (HTTP: m.weibo.cn 搜索接口, 关键词1)
  → 3-搜索请求 (关键词2)
  ... 每个关键词一个 HTTP 节点（n8n 的 HTTP 节点一条请求一个节点，不并发）
  → 4-搜索响应合并 (Code: 展平 data.cards[].mblog → posts[])
  → 5-风控检查 (IF: HTTP 432/403 或 ok:-100 → 跳错误分支)
  → 6-逐条取评论 (Code + Loop: 每条微博取第 1 页评论)
  → 7-评论展平 (Code: data[] → 每条评论一条 post，带 parent_post_id)
  → 8-去重 (Code: content_hash = sha256(正文), 与 data/posts.json 比对)
  → 9-落库 (Read/Write Files: data/posts.json)
  → 10-调用分析 (HTTP/子工作流: POST 03 → action=extract_batch, items=新posts)
  → 11-落 items (Read/Write Files: data/items.json)
  → Error Trigger (W0) → 写 data/run_log.json 状态=连接失败/受限或延迟
```

**关键取舍**：n8n 的 HTTP 节点**一条请求一个节点**，做不了「一个节点循环 N 次」。所以评论抓取用 `Code` 节点实现循环（Node 22 的 fetch 可用），或拆成固定 3 条（够演示）。我倾向 **Code 节点内循环 fetch**：一个节点、代码可见、限速易控。

## 5. 与平台契约的衔接

采集器**不写自己的数据格式**，直接产出契约里的字段：

```json
{
  "source_post_id": "O1...",
  "source_url": "https://m.weibo.cn/detail/O1...",
  "text": "人民公园门口晒得站不住，树荫下能好点",
  "published_at": "2026-07-20T14:03:00+08:00",
  "fetched_at": "2026-07-20T14:10:00+08:00",
  "parent_post_id": null,
  "fetch_mode": "live"
}
```

- `fetch_mode: live` 表示实时抓取；`historical_sample` 表示历史回放（演示兜底）；`mock` 表示假数据。
- 这三个值会一路传到 `heat_perception.json` 的 `mode` 字段，**页面上要显示出来**，不能让人误以为实时数据是当前民意的全量。
