所有命令在仓库根目录执行。`topic1` 是 `npm run topic1 --` 的简写：

```sh
npm run test:topic1
npm run topic1 -- plan
npm run topic1 -- skill
npm run topic1 -- pack
npm run topic1 -- verify --artifact <打包输出的ZIP路径>
npm run topic1 -- local --port 5312
```

`local` 会从当前代码构建新镜像，再通过真实 HTTP API 检查注册、默认本地工具、目标保存、候选生成与采用、报告和第二账户隔离；重启本次自己的容器后检查会话、目标、候选、情景、报告与隔离仍保留。验收密码、Cookie 只存于进程内存，不写入运行记录。不自动运行模型或采集。容器与命名卷保留，地址为 `http://127.0.0.1:5312/?view=workflow`；该端口被占用时直接停止，不接管现有服务。每次运行目录及 Compose 项目名写入 `.runtime/topic1/`。

如需使用已有缓存镜像，可传 `--node-image node:25.9-trixie-slim`，并保留实际版本。生产默认仍是 Node 24。后续停止仅操作本次记录中的项目名：

```sh
docker compose --project-name <本次project> --env-file <本次local.env路径> -f deploy/huawei/compose.yaml stop workbench
```

OBS 操作在拥有明确资源后执行：复制 `target.example.json` 到被 Git 忽略的 `target.json`，填写区域与真实桶名。`create_bucket: false` 复用桶；设为 `true` 会创建桶。访问凭证通过部署会话环境变量 `HUAWEICLOUD_SDK_AK`、`HUAWEICLOUD_SDK_SK` 和可选 `HUAWEICLOUD_SDK_SECURITY_TOKEN` 注入，不写入配置或命令行参数。

```sh
npm run topic1 -- obs --artifact <ZIP路径> --target deploy/huawei/target.json
# 核对计划并已获准操作对应资源后才执行下一条
npm run topic1 -- obs --artifact <ZIP路径> --target deploy/huawei/target.json --execute
```

上传对象名为 `urbancool/releases/<包SHA-256>.zip`，记录真实步骤、HTTP 状态和请求 ID，不记录凭证或上游错误正文。桶或凭证缺失时零调用并返回 `not_run`；操作失败后停止，不自动重试创建或修改权限。上传后仅复核对象长度，不声称已下载复核全部远端字节。私有源码包以 OBS 作为交付存储，尚无应用业务数据读写、RDS 或 Redis 集成。

已有 ECS 上运行 `sh deploy/huawei/deploy.sh deploy/huawei/.env`。它只负责 Compose 构建启动，不申请 ECS、不自动配置域名／证书／安全组。反代完成后运行 `npm run topic1 -- probe --origin https://实际域名`，再进行真实账户验收。云厂商、资源 ID 与 CodeArts 使用证据需从实际控制台和任务记录另行取得。

技能位置和导入格式依据：[CodeArts Skills 文档](https://support.huaweicloud.com/usermanual-codeartsagent/codeartsagent_ug_0024.html)。OBS SDK 依据：[安装](https://support.huaweicloud.com/sdk-nodejs-devg-obs/obs_29_0202.html)、[创建桶](https://support.huaweicloud.com/sdk-nodejs-devg-obs/obs_29_0301.html)、[文件上传](https://support.huaweicloud.com/sdk-nodejs-devg-obs/obs_29_0404.html)。当前自建技能通过格式检查，并不代表已取得官方技能认证或赛事验收。

## 本机容器验收

需已有 Docker 引擎。在仓库根目录执行：

```sh
docker build --target cloud -t urbancool-workbench:topic1 .
docker run --rm --name urbancool-topic1-local -p 127.0.0.1:5297:5181 \
  -e URBANCOOL_SITE_ORIGIN=http://127.0.0.1:5297 \
  -v urbancool-topic1-local:/app/.runtime urbancool-workbench:topic1
```

打开 `http://127.0.0.1:5297/?view=workflow`，使用独立验收账户。健康检查只确认应用和账户存储可用，不代表语言模型或温度模型已就绪。

2026-11-19 验收：`test:cloud` 12 项、`test:accounts` 12 项通过；默认测试 126 项通过、2 项跳过，账户版构建通过。默认 Node 24 镜像因 Docker Hub 鉴权网络超时未能拉取；另用本机缓存的官方 `node:25.9-trixie-slim` 构建并运行隔离容器，验证健康检查、默认本地工具、禁用新采集、账户及工程在容器重启后保留、非 root 只读运行。生产模板仍使用 Node 24，其镜像构建须在网络可用时另行验收。

## 华为云部署准备

以已有 ECS 上的 Docker Compose 为一种应用承载方式；该方案需在 CodeArts 中通过实际可用的已有智能体／Skills 适配和执行，并补齐关联云服务环节。

1. 将代码放到部署主机，复制 `deploy/huawei/.env.example` 为同目录 `.env`，填写实际 HTTPS 源、端口和已开通的 MaaS 模型 ID。不要提交 `.env`。
2. 运行 `docker compose --env-file deploy/huawei/.env -f deploy/huawei/compose.yaml config` 检查配置，再用同样参数执行 `up -d --build`。
3. 在同一主机上将实际域名的 HTTPS 页面与 `/api/agent` 请求反代到 `127.0.0.1:5181`，保留原始 Host；证书与域名由真实部署环境配置。
4. 检查 `/healthz`，再执行账户隔离和七步流程验收。命名卷由 Compose 保留；更新应用时保留该卷。
5. 记录实际镜像摘要、云资源和区域、Skills 操作与验收运行 ID。参考 `deploy/huawei/evidence.example.json` 建立真实记录；该模板本身不是执行证明。

构建上下文只允许应用所需文件。研究权重、浏览器 Cookies、`.env.local`、私人账户库和加密文件不进入镜像。

## 可选的本地 V3 温度模型镜像

基础镜像不包含 Python、研究权重或 GPU 服务。需要本地 CPU 试算时，使用 `compose.v3.yaml` 叠加构建 `cloud-v3` 目标。先将完整、已核验的实验目录放到部署主机，并在 `.env` 中设置其绝对路径 `URBANCOOL_LST_DIR`。

```sh
docker compose --env-file deploy/huawei/.env -f deploy/huawei/compose.yaml \
  -f deploy/huawei/compose.v3.yaml up -d --build
```

目录需包含 `tabular-v3/model.joblib`、`data-v3/manifest.json`、`test.jsonl` 和 `reference.jsonl`。模型挂载为只读。原模型及数据哈希门控继续生效；运行成功前不得将云端温度工具写成已验收。

## 华为云 MaaS

在工作台「模型设置」选择「华为云 MaaS」，填写控制台已开通、支持工具调用的模型 ID 及个人 API Key。默认使用中国区域的 OpenAI 兼容接口 `https://api.modelarts-maas.com/openai/v1`；已核对的亚太新加坡入口可由部署者用 `HUAWEI_MAAS_BASE_URL` 设置。
