# UrbanCool 工作台启动与验收

Windows 日常使用时，双击仓库根目录的「启动工作台.cmd」，也可以运行 `npm start`。它会更新有变更的页面构建，自动寻找本项目旁边的 V3 模型并核对能否推理，启动账户工作台，启动已有的 `urbancool-n8n` 或 `n8n` 容器，最后打开浏览器。已经运行的工作台和判定服务会复用。首次使用仍需安装依赖并配置判定工作流。

本机账户版后端启动时会自动检查并启动已有判定服务，包括需要时在后台启动已安装的 Docker Desktop。采集页每 15 秒检查一次；发现服务停止时自动恢复，同时显示「正在启动」。浏览器登录失效时，需在带 OpenCLI 扩展的浏览器中登录小红书并保持打开。点击「重新检查」可立即刷新状态。登录工作台与登录小红书不会代替工作流健康检查。

`URBANCOOL_CLASSIFIER_ORIGIN` 指定本机判定服务地址，默认 `http://127.0.0.1:5678`；需与容器的宿主机端口一致。Windows 预留该端口时，维护者应保留原工作流数据卷，调整容器映射和此项配置，再重启工作台。网页检查、MCP 和两个平台的后台判定使用同一配置。当前开发机已迁移到回环端口 15678，原容器作为停止状态备份保留。

自动恢复只用于监听本机回环地址的账户版，并且仅启动已有容器，不安装服务或创建云资源。`URBANCOOL_CLASSIFIER_AUTOSTART=0` 可关闭；云端模式不自动启动 Docker。失败后有重试间隔，同一时间只执行一轮恢复。

2026-11-19 实机验收：在没有活动采集任务时停止判定容器，从已登录账户进入采集页，观察到「正在启动」后自动恢复为三项「已就绪」，「开始采集」按钮可用。本次只验证健康与恢复，没有新增平台采集或模型付费调用。

工作台使用 Node.js 22.12 或更新的版本。在仓库根目录运行下面的命令，使用同一个 Node 进程提供页面、账户和 Agent API。

```powershell
npm ci
npm run build:accounts
npm run start:accounts
```

打开 <http://127.0.0.1:5181/> 后注册或登录。Windows PowerShell 可以使用 `npm.cmd` 执行上述命令。数据库默认是 `.runtime/accounts/workspace.sqlite`。单独验收可先将环境变量 `URBANCOOL_ACCOUNT_DB` 指向新的数据库文件。

从顶部「规划流程」按计划书的七个环节进入项目、资料、目标、地图编辑、手动评价、修改和成果输出。也可使用 `?view=workflow` 直接打开流程面板。「版本与成果」显示已保存的温度情景对照、报告是否对应当前版本，并可下载带逐件哈希的规划进度包。操作顺序与尚待接通的能力见[计划书对照与后续验证](计划书对照与后续验证.md)。

在「目标与草案 → 旧温度情景」中点击「以此范围新建版本」，可将旧矩形范围按当前目标重新保存。旧版本及其结果保留；新版重新核价，温度等待手动评价。当前情景和版本对照分别显示数值约束，超预算、超声明面积或费用不一致会显示冲突。模型运行不会使这些冲突自动通过。进度包新增独立的修改来源和约束检查文件，均纳入哈希清单。

「地表温度情景试算 → 用户保留范围」可在已登记 B 试算区内两点框选矩形，填写保留用途后保存。粉色为保留区；存在重叠的改造范围标红，并显示冲突名称和面积。与保留区有正面积重叠时，保存、恢复旧范围及评价都会被后端拒绝。仅接触边界允许通过。添加或明确解除保留约束会保存历史，创建新的当前情景快照，等待重新评价。进度包包含保留区 GeoJSON 和全部约束版本。此功能记录用户声明，不代替现场及法定保护条件核查。

「用户优先区域」可在同一登记范围内框选矩形并填写优先原因，蓝色显示。覆盖表分别列出候选 A、B 和当前温度情景与当前优先区域的相交面积，重叠区域只计一次，同时显示保留区冲突。添加或移除优先区域会保存独立版本，使已有报告标为旧版；已有情景、费用和温度运行结果保持原样，不自动计算。语言模型可读取优先区域和覆盖比较，修改仍由用户面板操作。覆盖面积用于讨论空间偏好，不表示降温、受益人口或实际使用效果，也不自动生成布局。

进度包增加 `用户优先区.geojson`、`优先区域版本.json` 和 `优先覆盖比较.json`，纳入逐件哈希清单。2026-11-21 独立账户实测见[优先区域验收](../verification/2026-11-21/priority-acceptance.json)。

### 按当前约束生成空间候选

在「本轮目标配置」填写预算和假设单价，点「保存预算与单价」。该动作只保存条件；固定 A/B 参考比较仍有独立入口。然后到「按约束生成空间候选」填写希望至少改造的整数面积，点击生成。可先在下方登记保留区和优先区域。

搜索限于已登记的 B 试算区，穷举 1 米整点、轴对齐的单矩形，逐项检查最低面积、面积上限、预算和保留区。费用按假设单价计算并保留两位小数。候选分别取满足最低面积的较低费用、较大面积和较多优先覆盖；并列时按紧凑程度及固定坐标顺序取一个。未设置优先区域时不生成该取向，相同几何会合并，不保证每次都有三个不同候选。

点击「地图查看」核对范围，再点「采用候选」创建新的温度情景。采用只保存范围与搜索来源，温度等待手动评价。改变预算、面积条件、保留区、优先区域或来源后，旧候选只能回看；后端也会拒绝采用过期候选。没有可行解时保留空结果，并说明最低面积、费用等限制，不会自动缩小用户目标。

报告与进度包保存搜索条件、算法版本、检查数量、筛选记录、候选和采用来源，新增 `空间候选搜索.json` 与 `搜索候选.geojson`。本功能比较的是声明条件下的单矩形空间取舍；未按降温排名，不代表已核实现场或得到城市尺度最优布局。

地图首页的「城市总览 · 试用」可查看覆盖范围和研究网格。总览可以定位网格，也可以打开成都例子，进入同一工作台的方案比较、报告和 AI 规划助手。

## 队友试用入口

在团队选定的主机上运行账户版。将域名的 HTTPS 请求（页面和 `/api/agent`）一并反代到本机 `127.0.0.1:5181`，将 `URBANCOOL_SITE_ORIGIN` 设置为实际 HTTPS 源，例如 `https://urbancool.example.org`。应用会为该 HTTPS 源启用 Secure Cookie，并在服务端校验请求来源。直接维护现有 SQLite 时，备份和恢复应同时保留数据库与同名 `.key` 文件。GitHub Pages 的静态构建继续使用 `npm run build`。

Qwen 服务地址与模型可用 `QWEN_BASE_URL`、`QWEN_MODEL`、`QWEN_SPECIALIST_MODEL` 设置。本机 Qwen 服务离线时，页面会提示，可以直接用落图试点的表单或示例比较来核算面积、费用和生成报告。历史温度需要配置 `URBANCOOL_LST_ROOT` 与 `URBANCOOL_LST_PYTHON`，详见[历史地表温度样例](成都落图试点.md#历史地表温度样例)。

启动器会分别报告 V3 温度工具与 Qwen 对话服务的状态。助手打开且没有执行协作任务时，每 15 秒检查一次模型连接，也可点击「重新检查模型连接」。连接提示区分推理服务不可达、模型加载中、认证失败和就绪状态未确认。状态检查只读取健康接口；真实问答需另行实测。使用云端 Qwen 时，先开启已有实例，启动其推理服务，再按[团队配置说明](团队试用与配置说明.md#要用-ai-对话)保持 SSH 转发运行。对话失败时，问题会保留在输入框中，方便连接恢复后重试。

「查微博历史归档」和「查小红书归档」通过本地 MCP 读取各自的成都历史抽样。展开本轮依据可核对平台、时间、内容哈希及小红书原笔记。小红书归档与地图侧栏读取同一份快照。归档查询无需启动采集服务。

「采集小红书」按成都关键词提交新任务，复用组员的搜索、判定和汇总流程。采集机器需要配置 OpenCLI 浏览器桥并登录小红书，同时运行 n8n 的 `03-demand-agent-api` 工作流。结果按账户保留，页面显示本次采集时间。参见[小红书模块说明](../xiaohongshu_demand_agent/README.md)。

采集默认请求后台浏览器窗口，工作台持续显示进度。完成后，本批市内文本会显示为线索卡，保留正文或一级评论的类型、主题、文本地点线索、记录日期、采集时间和原文链接。「加入现场核查清单」按账户保存该条线索的来源快照，重复点击会复用已有记录。

从助手上方的「现场核查清单」可补充核实位置和现场记录。选择「已核查」时需填写这两项。旧页面保存冲突会提示重新读取。清单可以导出为 Markdown，包含原文及批次和文件哈希。「带入规划讨论」将选中线索与人工记录放入对话输入框，检查后发送给助手。文本地点仍由人核对与当前场地的关系。

核查清单支持按状态、地点、主题、原文或现场记录搜索；导出只包含当前筛选中的已保存记录。未保存草稿按账户保留在当前浏览器标签页，切换助手视图后可恢复，关闭标签页后不保留。重新读取遇到更新版本时，先对照账户中的最新记录，再选择采用最新记录或继续编辑草稿。回到原批次采集页时会恢复「已加入清单」状态。采集连接短暂中断后会自动重试。

「关联研究场地」可人工选择当前已登记的研究网格，并随核查记录保存。关联表示将线索纳入该场地的调查安排；具体体验发生位置仍需填写和核实。「当前场地」筛选只读取已保存的关联。「地图查看网格中心」定位到来源网格中心，原文中的地点另看核实位置。导出清单记录场地关联时间、中心参考点及来源文件哈希。关联、筛选、导出和地图查看均可在 Qwen 离线时使用。

采集器默认使用 PATH 中的 Agent Reach，也可以在 `.env.local` 用 `AGENT_REACH` 指定可执行文件绝对路径。机器已有 OpenCLI 时，可以设置 `OPENCLI_ENTRY` 为 OpenCLI 安装包中 `package.json` 的 `bin.opencli` 所指文件的绝对路径。设置后工作台直接调用 OpenCLI 的小红书查询命令。修改配置后重启工作台。

「采集最新微博」按关键词发起新搜索，从能搜到的微博及一级评论中保留近 7 天发布的内容。工作台按账户保存结果和实际采集时间。实采待验收。采集机器需要在 Edge 登录微博并用 `weibo-demand-agent/scripts/refresh-cookie.ps1` 刷新本地凭证，同时启动 n8n 并启用仓库内的 [03-demand-agent-api 判定工作流](../xiaohongshu_demand_agent/workflows/03-demand-agent-api.json)。采集状态和凭证保存于本机。

## 接入组员的 MCP 服务

部署者在 `.env.local` 中登记 Streamable HTTP 服务地址和已审核的只读工具名。可登记多个服务，每个账户可选择启用其中一个。内置成都微博热感知走本地 stdio。

```dotenv
URBANCOOL_MCP_SERVERS=[{"id":"team_gis","label":"组内规划资料","url":"https://gis.example.org/mcp","tools":["search_sources"],"token_env":"URBANCOOL_MCP_TOKEN_GIS"}]
URBANCOOL_MCP_TOKEN_GIS=
```

地址和令牌替换为该服务的实际值。服务无需认证时省略 `token_env`。服务地址支持 HTTPS，本机联调也可用回环 HTTP。工具需要在 MCP 描述中声明 `annotations.readOnlyHint: true`。令牌由部署者在服务端配置，账户只保存选择的服务 ID。

重启工作台后，在「设置 → MCP 工具」选择服务，点「测试连接」查看发现的工具，再点「保存 MCP 设置」。启动语言模型后，可以说「用团队 MCP 查询这个场地的资料来源」。该轮只有资料核查 Agent 获得团队工具，结果保存在「本轮依据」。

## 用组员自己的问法验收

每位组员使用自己的测试账户，从成都工程样例进入落图试点。先比较两块候选，记录预算、面积上限和单价，再用自己的话分别测试以下操作。

| 操作 | 核对结果 |
| --- | --- |
| 从城市总览打开成都例子 | 地图定位到研究场地，可直接使用规划助手。 |
| 只改预算，沿用原单价和面积 | 只修改预算，旧版仍可查看。按 300 元/㎡ 核算并将预算改为 5 万元时，A 为 43,200 元，B 为 90,000 元且超预算。 |
| 新会话中报预算并说明单价未定 | 追问单价，保留缺项。 |
| 要求检查某个候选的预测状态，再明确取消预测 | 执行依据中记录指定候选的状态，取消后无预测检查。温差保持空值。 |
| 查询成都微博历史归档 | 依据中标明城市级快照、归档日期和 MCP。 |
| 查小红书归档 | 依据显示小红书快照、日期以及原笔记链接。 |
| 采集小红书 | 新任务按账户保留结果和采集时间。缺少采集依赖时显示原因。 |
| 采集最新微博 | 输入关键词后启动一批新采样，查看进度和实际采集时间。依赖缺失时显示原因。 |
| 导出报告后退出，再登录 | 恢复自己的方案和报告。另一个账户读取不到该会话。 |

保存原话、预期结果、实际结果以及「查看本轮依据」或导出的会话记录。要比较基座版与微调版，在模型设置切换后用新会话复跑同一批原话。自动回归可执行 `npm run test:agent` 与 `npm run test:accounts`。

## 通过 AI 对话生成空间候选

先进入成都落图试点并连接可用的对话模型，再发送明确条件，例如：

> 预算15000元，假设单价300元/平方米，最低改造面积10平方米，生成空间候选。

主 Agent 登记预算与单价，方案探索 Agent 调用真实有限搜索；最低面积不会登记成面积上限。后端核对本轮用户原话和已保存条件，不能由委派文字或模型补出数字。只在登记范围内检查1米整点单矩形，比较费用、面积和优先区域覆盖。没有优先区域时只比较前两项。

随后可以发送“预算改为2000元，最低面积不变，重新生成空间候选”。只有明确沿用最低面积或说明“其余条件不变”时才沿用上次下限；未指定或存在多个下限时要求补充，不自行选择。当前词法核验支持阿拉伯数字及平方米、平米、㎡等单位；无法确认的表述保留为缺项。

发送“查看现在的空间候选”会核对保存结果与当前条件。过期搜索不能作为当前推荐；如果本轮预算或单价的新值尚未登记，也不会推荐旧候选。搜索未执行、复用旧批次、当前批次无解和结果过期分别说明。关键数值由实际工具结果生成，模型摘要不能替换它们。

候选出现在「目标与草案」的候选卡片中，由用户查看地图并采用；采用后再手动评价温度。语言模型没有采用、修改保留／优先区域或运行覆盖温度试算的工具权限。未连接对话模型时仍可通过表单生成候选。

2026-11-21 本轮软件验收使用脚本化模型响应驱动真实委派和搜索；默认本机 Qwen 入口未连通，真实 Qwen 问答效果待实测。验收不表示已证明降温、现场可行或任意多地块最优。

后续连接与实测使用[统一 Qwen 接入说明](Qwen主Agent接入.md)。各启动入口默认18084、主模型`epoch_2`、专业模型`base`，均读取`.env.local`；显式配置优先。服务恢复后运行 `npm run verify:spatial:live -- --output verification/新的独立验收目录`。它逐轮保存六类问法的检查和工具证据，离线记录为`not_run`，不会以工具夹具结果代替真实模型验收。
