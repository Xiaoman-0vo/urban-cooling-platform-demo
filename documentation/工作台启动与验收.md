# UrbanCool 工作台启动与验收

工作台使用 Node.js 22.12 或更新的版本。在仓库根目录运行下面的命令，使用同一个 Node 进程提供页面、账户和 Agent API。

```powershell
npm ci
npm run build:accounts
npm run start:accounts
```

打开 <http://127.0.0.1:5181/> 后注册或登录。Windows PowerShell 可以使用 `npm.cmd` 执行上述命令。数据库默认是 `.runtime/accounts/workspace.sqlite`。单独验收可先将环境变量 `URBANCOOL_ACCOUNT_DB` 指向新的数据库文件。

地图首页的「城市总览 · 试用」可查看覆盖范围和研究网格。总览可以定位网格，也可以打开成都例子，进入同一工作台的方案比较、报告和 AI 规划助手。

## 队友试用入口

在团队选定的主机上运行账户版。将域名的 HTTPS 请求（页面和 `/api/agent`）一并反代到本机 `127.0.0.1:5181`，将 `URBANCOOL_SITE_ORIGIN` 设置为实际 HTTPS 源，例如 `https://urbancool.example.org`。应用会为该 HTTPS 源启用 Secure Cookie，并在服务端校验请求来源。直接维护现有 SQLite 时，备份和恢复应同时保留数据库与同名 `.key` 文件。GitHub Pages 的静态构建继续使用 `npm run build`。

Qwen 服务地址与模型可用 `QWEN_BASE_URL`、`QWEN_MODEL`、`QWEN_SPECIALIST_MODEL` 设置。本机 Qwen 服务离线时，页面会提示，可以直接用落图试点的表单或示例比较来核算面积、费用和生成报告。历史温度需要配置 `URBANCOOL_LST_ROOT` 与 `URBANCOOL_LST_PYTHON`，详见[历史地表温度样例](成都落图试点.md#历史地表温度样例)。

「查微博历史归档」和「查小红书归档」通过本地 MCP 读取各自的成都历史抽样。展开本轮依据可核对平台、时间、内容哈希及小红书原笔记。小红书归档与地图侧栏读取同一份快照。归档查询无需启动采集服务。

「采集小红书」按成都关键词提交新任务，复用组员的搜索、判定和汇总流程。采集机器需要安装 Agent Reach、配置 OpenCLI 浏览器桥并登录小红书，同时运行 n8n 的 `03-demand-agent-api` 工作流。若 Agent Reach 不在 PATH，可在 `.env.local` 用 `AGENT_REACH` 指定可执行文件绝对路径。结果按账户保留，页面显示本次采集时间。参见[小红书模块说明](../xiaohongshu_demand_agent/README.md)。

「采集最新微博」按关键词发起新搜索，从能搜到的微博及一级评论中保留近 7 天发布的内容。工作台按账户保存结果和实际采集时间。实采待验收。采集机器需要在 Edge 登录微博并用 `weibo-demand-agent/scripts/refresh-cookie.ps1` 刷新本地凭证，同时启动 n8n 并启用仓库内的 [03-demand-agent-api 判定工作流](../xiaohongshu_demand_agent/workflows/03-demand-agent-api.json)。采集状态和凭证保存于本机。

## 接入组员的 MCP 服务

部署者在 `.env.local` 中登记 Streamable HTTP 服务地址和已审核的只读工具名。可登记多个服务，每个账户可选择启用其中一个。内置成都微博热感知走本地 stdio。

```dotenv
URBANCOOL_MCP_SERVERS=[{"id":"team_gis","label":"组内规划资料","url":"https://gis.example.org/mcp","tools":["search_sources"],"token_env":"URBANCOOL_MCP_TOKEN_GIS"}]
URBANCOOL_MCP_TOKEN_GIS=
```

地址和令牌替换为该服务的实际值。服务无需认证时省略 `token_env`。服务地址支持 HTTPS，本机联调也可用回环 HTTP。工具需要在 MCP 描述中声明 `annotations.readOnlyHint: true`。令牌由部署者在服务端配置，账户只保存选择的服务 ID。

重启工作台后，在「设置 → MCP 工具」选择服务，点「测试连接」查看发现的工具，再点「保存 MCP 设置」。启动语言模型后，可以说「用团队 MCP 查询这个场地的资料来源」。该轮只有资料核查 Agent 获得团队工具，结果保存在「本轮依据」。

## 用组员自己的问法验收

每位组员使用自己的测试账户，从成都工程样例进入落图试点。先比较两块候选，记录预算、面积上限和单价，再用自己的话分别测试以下操作。

| 操作 | 核对结果 |
| --- | --- |
| 从城市总览打开成都例子 | 地图定位到研究场地，可直接使用规划助手。 |
| 只改预算，沿用原单价和面积 | 只修改预算，旧版仍可查看。按 300 元/㎡ 核算并将预算改为 5 万元时，A 为 43,200 元，B 为 90,000 元且超预算。 |
| 新会话中报预算并说明单价未定 | 追问单价，保留缺项。 |
| 要求检查某个候选的预测状态，再明确取消预测 | 执行依据中记录指定候选的状态，取消后无预测检查。温差保持空值。 |
| 查询成都微博历史归档 | 依据中标明城市级快照、归档日期和 MCP。 |
| 查小红书归档 | 依据显示小红书快照、日期以及原笔记链接。 |
| 采集小红书 | 新任务按账户保留结果和采集时间。缺少采集依赖时显示原因。 |
| 采集最新微博 | 输入关键词后启动一批新采样，查看进度和实际采集时间。依赖缺失时显示原因。 |
| 导出报告后退出，再登录 | 恢复自己的方案和报告。另一个账户读取不到该会话。 |

保存原话、预期结果、实际结果以及「查看本轮依据」或导出的会话记录。要比较基座版与微调版，在模型设置切换后用新会话复跑同一批原话。自动回归可执行 `npm run test:agent` 与 `npm run test:accounts`。
