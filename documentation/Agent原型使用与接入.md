**2026-10-25更新：**已接入“主Agent＋资料核查、方案探索、预测评估”框架，新增“协作任务”页签。角色权限、任务状态、调用预算和接入位置详见[多Agent框架说明](多Agent框架说明.md)。下方2026-10-24联调记录保留为当时的单Agent验收快照。

第一次体验请按[从零跑通系统操作教程](从零跑通系统_操作教程.md)逐步操作，里面有页面入口、可复制的问题和预期结果。

## 启动与试用

需要仓库原有的 Node/npm 环境与依赖。服务端读取系统环境变量 `DEEPSEEK_API_KEY`，也可以从 `.env.example` 复制出被 Git 忽略的 `.env.local` 后自行填写。不要将密钥写入前端或提交到仓库。

```text
npm run dev:agent
```

打开 `http://127.0.0.1:5173/`，点击右下角“AI 规划助手”。前端仍可单独用 `npm run dev` 运行；此时如果未另启 `npm run agent:server`，AI 面板会显示服务未连接。

依次尝试：

1. “请梳理当前已载入场地的真实资料，说明现有绿量和数据限制。”
2. “为什么现在还不能运行温度预测，缺哪些输入？”
3. “我给定的讨论假设是：预算10万元，候选面积800平方米，建设单价100元/平方米。保留建筑，生成三档配置目标，比较面积和费用。”
4. “把预算改成5万元，重新生成和比较。旧方案保留。”
5. “导出当前规划讨论记录。”

也可在“目标与草案”页填写三个声明条件。每次提交都会明确以用户提供的讨论假设发送给 Agent。打开面板、查看已保存记录不调用模型；发送问题或提交条件会产生 DeepSeek API 费用。

## 已实现

- 一个主 Agent，维护当前项目、对话、目标、方案版本与工具执行记录。
- 查询 `scene.json`、`macro_nodes.geojson` 的真实来源资料；显示引用位置和基线 SHA-256。
- 当前例子的绿色投影面积、斑块与源连通组等保持原来源口径。其他网格不借用示例指标。
- 从用户原话登记目标，拒绝未被明确提供的预算、容量或单价。固定保留建筑。
- 三档投入配置模板（50%/75%/100%），由本地程序计算面积、假设费用与预算/容量约束。
- 修改预算后保留旧草案，以目标版本区分当前与旧方案；明确记录未达到面积目标的缺口。
- 查询预测接入状态，返回 `not_run` 和空温度值；只有明确提出计算请求才受理此检查。
- 下载 Markdown 讨论记录或完整 Agent JSON 记录，包含假设、来源与版本。
- 按本地会话保存到 `.runtime/agent/sessions/`，重启服务后可以恢复。页面仅保存会话标识。
- 执行记录中的“查看位置”可以移动地图；不会改变来源资料或科研准入状态。

## 能力边界

配置目标尚无地物几何，不能当作真实改造布局或施工方案。候选面积和单价是用户声明，不是由现状空地自动推导；费用只计假设建设费。

没有接入完整情景编译器、冻结温度模型、物理模拟、可施工性核查或02/03/04联合计算。面积较大不能直接解释为降温更好。当前 Agent 的 DeepSeek 大模型与科研温度预测模型是两种不同模型。

Agent 会话与原有研究工程 JSON/ZIP 分开保存；页面中的原工程保存功能不会自动将 Agent 会话装入研究交接包。通过助手“导出记录”单独保留。

GitHub Pages 及原静态 Worker 仍只提供静态页面。本地 Agent 后端绑定回环地址；线上协作需要另行部署并增加账户、权限、访问控制和持久化设计。此原型没有创建云端服务或修改公网部署。

## 代码与接口

| 文件 | 职责 |
|---|---|
| `server/agent-tools.mjs` | 来源查询、参数检查、目标/方案/报告工具 |
| `server/project-agent.mjs` | DeepSeek 适配、主 Agent 指令和有界工具循环 |
| `server/agent-server.mjs` | 本地 HTTP API、会话落盘、来源检查与错误处理 |
| `src/AgentPanel.jsx`、`src/agent.css` | 对话、目标表单、方案卡片、依据与导出 |
| `scripts/dev-agent.mjs` | 同时启动前端和本地 Agent 服务 |
| `tests/agent.test.mjs` | 工具约束、版本隔离、错误处理及本地 API 检查 |

接口：`GET /api/agent/health`、`POST /api/agent/sessions`、`GET /api/agent/sessions/{id}`、`POST /api/agent/chat`。默认后端端口5181，前端5173，Vite代理调用；前端请求使用已有 `BASE_URL`。

当前整轮协作最多16次模型请求、36次工具操作、6次委派，单次最多1800个输出token；主角色最多6轮、专业角色最多5轮，并受全局上限约束。服务端有单次请求和整轮超时。工具参数及角色权限由后端校验，模型没有任意执行脚本、访问任意文件或请求任意网址的工具。外部服务错误只返回受控信息，不回显凭证。

## 本机联调验收（2026-10-24）

已通过页面向 DeepSeek 官方 API 完成5轮对话、14次模型请求和10次实际工具调用：查询场地、登记条件、生成草案、修改预算、导出报告，以及重启服务后的会话恢复。仅使用用户授权的公开场地摘要和演示规划条件。

预算10万元、声明面积800㎡、假设单价100元/㎡时，三档面积为400/600/800㎡，费用为4/6/8万元。预算改成5万元后，新版本为250/375/500㎡，费用为2.5/3.75/5万元；三个旧版草案保留。所有草案几何和预测温度仍为空。

`npm run build` 通过；默认软件检查89项，87项通过、2项按原定义跳过；最终补充修改后的13项 Agent 检查再次全部通过。这些是软件和联调验收，不代表科研温度模型已经执行。

联调中大模型曾在复述旧版数值时出现一次口误并自我更正，程序卡片和报告的数值正确。已收紧自然语言回答格式；后续仍需评估事实一致性，关键面积和费用应核对程序结果。

## 后续接入

下一步应由科研侧提供冻结推理包、编码器、完整输入图、固定验证样例及允许干预的特征映射。新增独立的模型适配器与运行合同，保持现在的 `not_run`、空值与失败状态区别；通过实际验收后才开放预测功能。

当前已拆分专业Agent，但真实空间搜索仍待接入。未来工具可以通过MCP对外封装，固定报告或分析流程可整理成Skill；它们应复用同一套后端校验与版本对象。
