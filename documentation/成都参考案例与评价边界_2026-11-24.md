# 成都登记场地：评价参考案例（2026-11-24）

## 案例身份与用途

本案例使用 E4125_N33891 已登记的成都来源几何和2022-09-28历史地表温度数据。它是基于真实来源资料的模型响应诊断，不是已经实施的改造项目。用户确认目前没有现场核查条件；现场植栽、权属、实际降温、人体热舒适和使用者效率均保持未验证。

用于讨论的条件为预算40000元、假设建设单价300元/㎡、最低面积102㎡。这是可重复执行的开发验收任务，不是现场使用者提供的真实工程报价或需求访谈。

## 预先固定的对照

| 对照 | 范围／面积 | 目的 |
| --- | --- | --- |
| 现状参考 | 原历史网格，不做覆盖变化 | 记录观测与模型基线，避免把基线预测当成观测 |
| 面积51㎡ | 3×17米 | 输入响应诊断；未达到讨论最低面积，不作为可选方案 |
| 面积102㎡左侧 | 6×17米 | 最低面积规则参照，假设费用30600元 |
| 面积102㎡右侧 | 6×17米，改变位置 | 检查同面积不同布局是否进入模型 |
| 面积128㎡ | 8×16米 | 当前预算内扩大面积的代表候选 |
| 面积153㎡ | 9×17米 | 全登记区诊断；假设费用45900元超预算，不作为可选方案 |
| 重复102㎡左侧 | 完全相同的输入 | 检查重复运行的一致性 |

协议在执行前写入 [protocol.json](../verification/2026-11-24/case-evaluation/protocol.json)，上限7次冻结模型推理；没有根据结果反复更换范围或筛选正降温。模型、登记文件和冻结数据未修改，也没有训练。

## 实际结果

| 对照 | 模型温差（基线减情景） |
| --- | ---: |
| 51㎡ | −0.016℃ |
| 102㎡左侧 | −0.058℃ |
| 102㎡右侧 | −0.058℃ |
| 128㎡ | −0.058℃ |
| 153㎡ | −0.026℃ |
| 重复102㎡左侧 | −0.058℃ |

模型基线32.970℃；该网格同日Landsat历史观测33.567℃，本样本预测误差为−0.597℃。这是一个历史样本的残差，不能当作模型整体误差、方案温差的置信区间或判断实际有效性的阈值。

可从这次记录确认：

- 同一输入重复运行得到相同结果。
- 102㎡左右两个位置编译后的模型输入完全相同，当前模型不能依据这些输入辨别布局差异。
- 面积变化产生了模型响应，但没有形成面积越大越凉的单调关系；本次所有诊断温差为负。
- 相对102㎡规则参照，128㎡多改造26㎡、多投入7800元，在当前三位小数输出精度下没有不同的模型温差。

0.001℃仅为当前输出显示精度，不是误差界限。未测量差值不确定性，不能用微小差异证明实际效果优劣。实际原始输出、模型及数据哈希见 [results.json](../verification/2026-11-24/case-evaluation/results.json)。

## 参照与验收口径

102㎡参照由“满足最低面积×声明单价”的明确规则建立，不冒充真实人工规划方案，也没有人工耗时数据。本轮检查模型输入与输出是否忠实、差异能否解释、条件冲突能否保留；不能宣称比人工规划更快或更有效。

后续需要独立补充：现场范围和用途、植栽条件、可信干预效果资料、热舒适评价、真实使用者完成任务的时间与错误记录。没有这些证据前，系统只能支持历史覆盖假设的比较与核查准备。

## 同日软件复核

CodeArts 根据宿主复现的失败用例修复评价适用性模块。同一冻结基准、相同模型输入出现不同显示温差时，系统保留原值并标记不可比；三个以上候选中任意同输入组的冲突也需阻止选优。页面、报告和进度包沿用同一判断，手动重试重新计算并保留旧评价。人工构造的冲突数据只用于软件回归测试，不登记为真实模型诊断结果；上表7次实际诊断结果没有改写。
