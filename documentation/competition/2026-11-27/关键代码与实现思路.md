## 01 用户目标必须有原话依据

源码：[server/agent-tools.mjs](../../../server/agent-tools.mjs#L104)，L104至L118。

**问题与思路**：自然语言中经常混有建议数值、旧预算和用户本轮的真实约束。错误登记会改变后续候选范围。 把目标登记设计成服务端校验工具。预算、面积和单价必须在本轮用户原话中出现，并按字段核对数值与单位；不让语言模型自行补足。

## 02 用状态图组织模型和工具循环

源码：[server/agent-runtime.mjs](../../../server/agent-runtime.mjs#L98)，L98至L116。

**问题与思路**：一次回答可能需要读取场地、调用工具并继续推理，单轮聊天难以表达任务执行状态。 使用 LangGraph 将模型请求、工具执行和回答核查连接为状态图。每个角色复用同一循环，并设置最大轮次与递归限制。

export async function runRoleLoop({messages,maxRounds=5,...runtime}) {
  runtime.task.usage={input_tokens:0,output_tokens:0,model_requests:0};
  const allowed=new Set(runtime.tools.map(tool=>tool.function.name));

**验证与限制**：本轮默认测试包含 Agent、多角色协作和工具循环检查。 状态图是编排机制，不证明每个回答正确；真实大模型服务的可用性需要独立验收。
