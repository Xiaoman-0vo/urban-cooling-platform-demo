# 成都 E4125_N33891 落图试点

试点使用已有样例网格与基线。候选 A 取自 H2 审阅面内的 144 平方米矩形，候选 B 取自 H1 审阅面内的 300 平方米矩形。服务启动时以 EPSG:32648 核查边界和面积，核对已有建筑、植被与两期道路中心线的空间关系，并记录各来源的 SHA-256。现场可改范围、植栽适宜性、权属、管控红线与道路实际范围由组员核实。

先加载样例场地，打开 AI 规划助手，进入“落图试点”。“查看候选范围”展示两块讨论范围。“按示例条件比较”发送预算 10 万元、面积上限 300 平方米、假设单价 300 元/平方米。接着请助手把预算改为 5 万元，沿用面积与单价，重新比较并导出。A 的假设费用为 43,200 元，B 为 90,000 元。改版后 B 标为超预算，两版边界都可查看。报告和地图版本可分别下载。

`npm run dev:agent:qwen` 同时启动本地页面和 Qwen Agent。该入口的主模型默认 `epoch_2`，专业模型默认 `base`，上游默认 `http://127.0.0.1:18084/v1`。如通过原实验服务器推理，先从其 V4 实验目录启动 `train_v4.py serve --port 18084`，再将远端 18084 转发到本机 18084。页面默认在 `http://127.0.0.1:5173/`。

试点将明确请求的预测检查交给后端工具执行并留痕。当前工具报告未接通、旧版待更新或超出声明条件。取消请求后不触发检查，温度输出保持为空。

两版报告和地图包含同一会话的两版候选。脚本化回归产物可对照查看。[两版报告](../verification/成都落图试点_两版对照.md) · [地图 GeoJSON](../verification/成都落图试点_两版对照.geojson)

启动本地页面和远端推理后，在仓库根目录运行 `node scripts/verify-planning-pilot-live.mjs`。脚本通过页面代理的 Agent API 实测初次比较、只改预算并导出、当前 A 的预测检查、超预算 B、指定旧版、取消预测和缺单价。Qwen 理解请求并调度工具。试点的费用、缺项和预测状态按工具记录生成回复，实测 JSON 分别保存页面回复和模型原文。七个用例由开发侧编写，组员仍可用自己的说法复测。[实测两版报告](../verification/成都落图试点_Qwen实测对照.md) · [实测地图 GeoJSON](../verification/成都落图试点_Qwen实测对照.geojson)

## 历史地表温度样例

本地 Agent 可以调用 V3 同日校准梯度提升树，估计三个留出日期中已登记网格的历史地表温度。输入限定为已校验的 Landsat 样本和同日参考区，来源、模型版本、观测时刻和文件哈希会保存在执行记录。A、B 方案的降温计算仍待接入。

在仓库根目录设置以下服务端环境变量，然后启动本地页面。实验目录应包含 V3 数据、模型和训练代码。Python 环境应安装 scikit-learn 1.7.2 与 joblib。

```powershell
$env:URBANCOOL_LST_ROOT = '../finetune-temperature-deepseek'
$env:URBANCOOL_LST_PYTHON = '<已安装依赖的 Python 可执行文件路径>'
npm.cmd run dev:agent:qwen
```

打开 AI 规划助手，点“运行历史温度样例”。也可以输入“估计 E4105_N33911 在 2022-09-28 的历史地表温度”。已通过浏览器验证，样例使用本机 CPU 推理，地表温度估计为 32.04℃，同日 Landsat 观测为 33.92℃。可在“执行依据”核对影像与模型版本。其他网格和日期需要在同一 V3 留出数据中有合格记录。

地图选中或定位到已登记网格后，可以问“这个格子 2022 年 9 月 28 日有多热？”。只问历史地表温度而省略日期时，助手会询问完整日期，可以直接回复“2022 年 9 月 28 日”。同一句有多个不同的网格或日期时，请指定一个。已通过本地 API 和真实 V3 模型复测。

多轮改参回归覆盖了先建方案、只改单价、只改面积上限、只改预算并导出四版。“从 X 改到 Y”的原值不再通过原话校验。四轮在本地用脚本化模型响应验证了实际后端计算与版本记录。Qwen V4 服务可用后，可运行 `node scripts/verify-planning-pilot-live.mjs --revisions`，用相同问题实测模型调度，输出独立于原七项联调的记录。题目由开发侧编写，组员独立出题仍待完成。

## 本机试用

沿用上面的两个温度模型环境变量，另设 `$env:URBANCOOL_LOCAL_TRIAL = '1'`，运行 `npm.cmd run dev:agent`，打开 `http://127.0.0.1:5173/`。选择“浏览真实工程样例”，再打开“AI 规划助手”和“落图试点”。“按示例条件比较”先跑 10 万元预算。随后在“目标与草案”只填 50000 元，点击“登记条件并生成草案”。旧版留在同一会话，可生成讨论记录及导出地图。试用的规划表单直接执行本地工具，历史地表温度在 CPU 上计算。

## 多账户工作台

使用 Node.js 22.12 或更高版本，在仓库根目录运行 `npm.cmd run dev:accounts`，打开 `http://127.0.0.1:5173/` 注册。右上角齿轮可设置模型和退出登录。每个账户分别保存一份工作台工程快照和各场地的 Agent 会话。旧的浏览器工程可先导出交接包，登录后重开并保存到自己的账户。

账户默认使用 UrbanCool Qwen 微调版。用 `QWEN_BASE_URL`、`QWEN_MODEL`、`QWEN_SPECIALIST_MODEL` 配置项目的推理服务。基座版和微调版使用同一套角色与工具。服务暂不可用时，可在设置中选本地规划工具。历史温度另用此前的两个 V3 环境变量。个人配置支持 DeepSeek API，管理员也可通过 `URBANCOOL_MODEL_ENDPOINTS` 登记兼容 API 的 HTTPS Base URL。模型配置保存后，在该账户发起模型对话时才调用对应服务。

账户数据默认在 `.runtime/accounts/workspace.sqlite`，密钥文件为同名 `.key`。备份数据库时应一并安全保留密钥文件。生产构建和队友验收见[工作台启动与验收](工作台启动与验收.md)。

## 同一试点的覆盖变化实验

在成都 `E4125_N33891` 上复用了 2022-09-28 的 Landsat 参考时刻和 1558 个同日参考格。原栅格重算得到的不透水面比例、树木／灌木覆盖比例、建筑高度特征与 V3 冻结输入相符。实验在中心格把 UBGG 的不透水面面积转入树木／灌木覆盖类别，沿用八邻格和建筑高度特征。[UBGG 分类说明](https://www.nature.com/articles/s41597-023-02844-2)

| 对象 | 栅格检查与转换条件 | 地表温度 |
| --- | --- | --- |
| 历史基线 | 不透水面 80.11%，树木／灌木覆盖 19.89% | 模型 32.970℃，Landsat 33.567℃ |
| 候选 A | 144㎡全部和 CNBH 正高度像元重叠。既有矢量屋顶检查通过，需核查两种资料的差异 | 未运行情景推理 |
| 候选 B | 300㎡中 140㎡与正高度像元重叠，160㎡高度缺测。假设这 160㎡经核查可改，转换后两个比例分别为 78.51% 和 21.49% | 模型 32.996℃，比模型基线高约 0.03℃ |

B 的差值是指定土地覆盖假设下的模型响应。真实施工条件和改造温度响应仍待验证，平台的方案温度入口仍停留在接入检查。输入、模型和来源哈希见[实验记录](../verification/成都落图试点_V3地表温度情景实验.json)。

候选现场需要确认的位置、资料与反馈格式见[候选现场核查](成都试点候选现场核查.md)。

在仓库根目录运行下列命令复现。Python 环境需要额外安装 Rasterio，数据使用已解压的 UBGG 和 CNBH 源栅格。

```powershell
& $env:URBANCOOL_LST_PYTHON server/historical-lst.py --experiment $env:URBANCOOL_LST_ROOT --grid E4125_N33891 --date 2022-09-28 --pilot .
```
