## 2026-11-21（第四轮）：从固定示例转为按约束生成候选

本轮改善的核心问题是：原工作台的 A/B 是固定讨论范围，用户修改预算和空间条件后，仍主要依赖手工重画，系统没有据此重新选择空间。现在新增登记范围内的有限单矩形搜索，串联条件保存、候选比较、地图查看、采用、版本和报告。

- 目标表单只保存预算与单价，不再顺带生成固定 A/B。用户明确填写最低改造面积后，程序检查全部 1 米整点单矩形，剔除违反预算、面积或用户保留约束的范围。
- 比较节约投入、扩大面积和优先覆盖三种取向；同一几何合并，无优先区域时明确省略该取向。优先覆盖为重叠面积的并集，不计重复部分。
- 无解保留空候选并解释限制；旧候选在条件改变后只读，采用接口复核条件、来源与当前情景，拒绝过期及跨会话候选。采用后创建结果为空的新情景，不自动运行温度模型。
- 搜索批次、条件和筛选数量、候选范围、采用来源及历史版本进入报告和进度包。搜索范围和离散目标可复核，不将结果称为降温最优或施工方案。

隔离账户的页面验收使用预算 15000 元、假设单价 300 元/㎡、最低面积 10㎡、2㎡用户保留区和20㎡优先区。程序检查 6885 个矩形，3054 个满足约束，得到 10㎡/3000元、50㎡/15000元、20㎡/6000元三个不同候选。采用第三个形成 v1；将预算改成2000元后旧候选禁用，重新生成明确返回无解（最低面积至少需要3000元）。恢复预算后重新生成并采用50㎡候选，形成v4，前三版保留。本次未运行语言模型、温度模型或云资源。

验证：账户版构建通过；默认146项中144通过、2项平台专用跳过；补充33项通过。新增7项搜索测试覆盖独立网格占用核对、约束与目标、无解、重复请求、过期与伪造输入、报告哈希，以及账户重启与隔离。真实降温、现场条件、多地块布局和语言模型完整业务流程仍需独立验收。

## 2026-11-21（第五轮）：AI 对话连接真实空间搜索

上一轮的空间搜索已能通过表单操作，但 Agent 提示词仍称“只有固定模板”，也没有对应的受限工具。本轮将真实搜索接入方案探索角色，并加入用户原话、最低面积与当前条件的一致性检查。

- 主 Agent 只登记用户本轮明确给出的预算、单价或面积上限，再委派方案探索；只有方案探索角色获得生成工具。其他角色不能绕过委派，模型不能采用候选、修改保留／优先区域或运行覆盖温度试算。
- 最低改造面积与声明面积上限分开核验。最低面积必须来自本轮原话；只有明确沿用最低面积或说明其余条件不变时才取上次下限。缺失、歧义、小数下限及引用不匹配不执行搜索。
- 用户修改预算、单价或面积上限但模型尚未登记时，生成和推荐都停下，避免沿用旧条件。取消或能力询问不能授权生成。工具只计算候选，不接受模型传入的候选几何或预制结果。
- 查询与回答检查搜索是否过期；必要的只读查询由程序补足。关键数量、面积、假设费用和优先覆盖由真实结果生成，并区分本轮搜索、复用和已保存记录。模型声称“已采用”“可降温8℃”等文字不能替换这些结果。报告导出仍保留原有记录。

使用脚本化模型响应运行三轮真实软件流程：15000元／300元每平方米／最低10㎡生成候选；预算降到2000元并明确沿用最低面积后返回无解；随后把最低面积改为20㎡时，故意把它传作面积上限的调用被拒绝，下限搜索仍按20㎡执行且无解。保留全部搜索历史，未采用候选或运行温度模型。数值与工具记录见[本轮机器验收记录](../verification/2026-11-21/spatial-dialogue-acceptance.json)。

验证：新增14项行为测试；最终默认回归160项中158通过、2项平台专用检查跳过；协作、搜索、账户、版本报告与 Qwen 适配相关69项通过；账户版构建通过。构建仍提示既有前端包体较大，本轮未调整打包结构。

实际模型边界：本轮只读检查默认本机 Qwen `127.0.0.1:18083/health`，返回 `model_unreachable`。因此本轮证明的是受限工具与软件协作链路，尚未验证真实 Qwen 对独立问法的识别与工具选择。未启动云实例、未新增付费模型调用、未运行温度模型或训练；原始科研资料、历史证据与门控不变。操作示例已加入[工作台验收说明](工作台启动与验收.md#通过-ai-对话生成空间候选)。

## 2026-11-21（第六轮）：统一模型连接与真实验收入口

继续检查真实 Qwen 接入时，发现客户端及独立后端沿用18083／`active`，而账户工作台及开发启动器使用18084／`epoch_2`。上一轮确实检查过18083，但它不能代表工作台18084的连接状态。本轮按实际工作台默认重新检查，18084仍未连通；本机登记的两条项目 SSH 连接均超时，不能据此断言实例已关机。

已完成的软件改动：

- 新增共享 Qwen 配置，统一默认18084、主模型`epoch_2`与专业模型`base`；工作台、独立后端、开发启动器和验收工具使用同一来源。独立后端和开发入口读取`.env.local`，已有进程环境变量及显式启动参数优先。18083／`active`仍可显式配置，历史服务器和旧证据不修改。
- 加入 `npm run verify:spatial:live -- --output 新的验收目录`，通过当前配置的真实 HTTP 推理接口运行六类对话，保存工具轨迹、显示回答、模型原始摘要及逐项检查。测试使用独立内存状态，过期查询使用初始状态副本，不改用户账户或已有工程。
- 验收区分通过、失败与未运行。模型离线或加载中时不发送推理请求；认证、连接等服务错误停止后续用例。工具越权尝试、失败的子任务和没有真实搜索的成功声明都不能通过。检查项在 JSON 中明确记录布尔值，不丢弃失败项。
