# UrbanCool 第一版试用说明

大家先拉 `feat/workbench-preview` 分支，用成都样例把工作台跑一遍。这版可以看地图、比较方案费用、查历史资料。要试 AI 对话、历史地表温度或新采集，再按下面各节配置对应的服务。

## 先把项目跑起来

需要 Node.js 22.12 或更新的版本。第一次下载项目，在终端运行下面的命令。已经克隆过的话，先执行 `git fetch origin`，再切到 `feat/workbench-preview` 分支。

```bash
git clone --branch feat/workbench-preview https://github.com/Xiaoman-0vo/urban-cooling-platform-demo.git
cd urban-cooling-platform-demo
npm ci
npm run build:accounts
npm run start:accounts
```

打开 [http://127.0.0.1:5181/](http://127.0.0.1:5181/)，注册自己的账号，密码至少 12 个字符。Windows PowerShell 如果拦了 `npm`，可以把上面的 `npm` 换成 `npm.cmd`。账户、工程和对话默认存在各自电脑的 `.runtime/accounts/workspace.sqlite`。

## 基础功能怎么试

| 功能 | 在哪里操作 |
| --- | --- |
| 城市总览和地图 | 地图首页点「城市总览 · 试用」，可以定位网格，或点「查看工程样例」打开成都例子。 |
| 成都 A、B 方案比较 | 打开成都例子，进「AI 规划助手 → 目标与草案」，填预算、假设单价和可选的面积上限。 |
| 改预算和导出报告 | 在同一会话修改预算，查看新版和旧版，再点「生成讨论记录」并下载。这里也可以导出各版地图 GeoJSON。 |
| 查微博和小红书历史归档 | 点「查微博历史归档」或「查小红书归档」，在「本轮依据」核对来源和日期，小红书样例还能查看原笔记链接。 |
| 保存和恢复 | 点「保存场地」，工程和会话按自己的账号保存。 |

第一次试可以把模型设为「本地规划工具」。在成都例子里填预算 **10 万元**、面积上限 **300㎡**、假设单价 **300 元/㎡**。A 是 **144㎡、43,200 元**，B 是 **300㎡、90,000 元**。再只把预算改成 **5 万元**，看看旧版是否还在，以及新版里 B 是否被标为超预算。

## 要用 AI 对话

点工作台右上角的齿轮，进「模型设置」。有可用的 DeepSeek API 时，选 DeepSeek，填自己的 API Key 并保存。接团队的 Qwen 服务时，到仓库根目录创建 `.env.local`，填下面三项，再重启工作台。

```dotenv
QWEN_BASE_URL=http://127.0.0.1:18084/v1
QWEN_MODEL=epoch_2
QWEN_SPECIALIST_MODEL=base
```

这里的 `127.0.0.1` 是运行工作台的那台电脑。如果 Qwen 跑在 AutoDL 上，可以用下面的方式转发端口。把示例的端口、用户名和主机名换成自己有权限使用的 SSH 登录信息，终端保持打开。

```bash
ssh -N -L 127.0.0.1:18084:127.0.0.1:18084 -p SSH_PORT SSH_USER@SSH_HOST
```

如果团队已经部署了大家都能访问的推理地址，就把 `QWEN_BASE_URL` 改成团队提供的地址。服务要求认证时，在服务端配置 `QWEN_API_KEY`。配置好后，在「模型设置」选微调版或基座版。可以先问「请核查这个场地有哪些资料，还缺哪些输入」，再打开「本轮依据」看实际调用了哪些工具。

## 要查历史地表温度

先拿到团队的 V3 模型和数据，实验目录里需要有 `tabular-v3/model.joblib` 以及 `data-v3/` 下的 `manifest.json`、`test.jsonl` 和 `reference.jsonl`。准备一个装了 `scikit-learn==1.7.2` 和 `joblib` 的 Python，然后在 `.env.local` 加上下面两项，路径换成自己电脑上的实际路径。

```dotenv
URBANCOOL_LST_ROOT=D:/UrbanCool/finetune-temperature-deepseek
URBANCOOL_LST_PYTHON=D:/UrbanCool/.venv/Scripts/python.exe
```

重启后，在 AI 规划助手点「运行历史温度样例」，或者问「估计 E4125_N33891 在 2022-09-28 的历史地表温度」。页面会分别显示模型估计和同日 Landsat 观测，能查的网格和日期以 V3 数据为准。 [成都试点与温度说明](https://github.com/Xiaoman-0vo/urban-cooling-platform-demo/blob/feat/workbench-preview/documentation/%E6%88%90%E9%83%BD%E8%90%BD%E5%9B%BE%E8%AF%95%E7%82%B9.md)

**A、B 方案改造后能降多少度，这一版还算不了。** 我们做过一次固定覆盖变化假设的离线实验。工作台里的方案预测入口目前只检查条件和接入状态，报告里的方案温差仍为空。演示时，历史地表温度、方案费用和实际降温效果要分开讲。 [离线情景实验记录](https://github.com/Xiaoman-0vo/urban-cooling-platform-demo/blob/feat/workbench-preview/verification/%E6%88%90%E9%83%BD%E8%90%BD%E5%9B%BE%E8%AF%95%E7%82%B9_V3%E5%9C%B0%E8%A1%A8%E6%B8%A9%E5%BA%A6%E6%83%85%E6%99%AF%E5%AE%9E%E9%AA%8C.json)

## 要试小红书和微博的新采集

新采集在采集机器上运行。先启动 Docker Desktop，在仓库根目录启动 n8n。

```bash
docker compose -f xiaohongshu_demand_agent/deploy/docker-compose.yml up -d
```

打开 [http://127.0.0.1:5678/](http://127.0.0.1:5678/)，导入 `xiaohongshu_demand_agent/workflows/03-demand-agent-api.json`。创建名为 `DeepSeek API` 的 Header Auth 凭据，Header 名填 `Authorization`，值填 `Bearer <你的 API Key>`。在「4-调用模型」节点选择这份凭据，保存并发布工作流。

- **小红书**。采集机器用 `npm install -g @jackwener/opencli` 安装 OpenCLI，再装 Chrome 浏览器桥，登录小红书并保持浏览器打开。工作台可以用已装好的 Agent Reach 调用 OpenCLI。也可以直接在 `.env.local` 设置 `OPENCLI_ENTRY`，填写 OpenCLI 安装包中 `package.json` 里 `bin.opencli` 对应脚本的绝对路径。用 `npm root -g` 可以找到全局安装目录。重启工作台后，点「采集小红书」，输入 `遮阴`。 [OpenCLI 官方浏览器桥](https://chromewebstore.google.com/detail/opencli/ildkmabpimmkaediidaifkhjpohdnifk)
- **微博**。采集机器先在 Edge 登录微博，然后在仓库根目录运行 `powershell -NoProfile -ExecutionPolicy Bypass -File weibo-demand-agent/scripts/refresh-cookie.ps1`，按提示刷新本地登录凭证。工作台里点「采集最新微博」，输入 `遮阴`。

n8n 已用人工样例跑过真实判定。两平台的历史归档可以直接查，新采集还需要在浏览器登录完成后用真实内容走一遍。 [工作台启动与验收](https://github.com/Xiaoman-0vo/urban-cooling-platform-demo/blob/feat/workbench-preview/documentation/%E5%B7%A5%E4%BD%9C%E5%8F%B0%E5%90%AF%E5%8A%A8%E4%B8%8E%E9%AA%8C%E6%94%B6.md)

## 要接组员自己的 MCP

如果你手上有现成的 MCP 服务，把工作台后端能访问的地址、工具名和一句测试问法给我。现在支持 Streamable HTTP，团队工具要在 `annotations` 里声明 `readOnlyHint: true`。部署时在 `.env.local` 登记要开放的工具。下面的地址和工具名是示例。

```dotenv
URBANCOOL_MCP_SERVERS=[{"id":"team_gis","label":"组内规划资料","url":"https://gis.example.org/mcp","tools":["search_sources"]}]
```

服务需要 Bearer Token 时，在该条配置里加 `"token_env":"URBANCOOL_MCP_TOKEN_GIS"`，再把 Token 写到同名服务端环境变量。重启后进「设置 → MCP 工具」，先测试连接再保存。现在每个账号可以启用一个登记好的团队服务。打开支持工具调用的模型后，可以问「用团队 MCP 查询桐梓林的规划资料」，在「本轮依据」确认返回结果。
