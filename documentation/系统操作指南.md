# UrbanCool 系统操作指南

适用版本：2026-11-23 本机试用工作台。

## 打开与登录

[打开试用系统](http://127.0.0.1:5312/?view=workflow)。打不开时双击 `D:\华为ICT大赛\启动试用系统.cmd`，启动器会后台恢复 Docker 和原试用容器，检查服务后打开网页。继续使用原试用账户。

新用户点击「注册新账户」，密码至少12个字符。系统账户与 CodeArts 账户独立。5312 与日常5181实例分别保存数据，不能混用账户。

5312 默认使用本地规划工具，已接入原 V3 冻结温度模型，关闭新社交媒体采集。浏览地图、生成候选和保存条件不会自动计算温度。

## 第一次完成候选比较

### 1. 载入场地

在「规划流程」点击「载入成都示范区」，确认显示 `E4125_N33891`。点击顶部软盘「保存场地」，保存地图工程，再打开顶部「方案工作台」。

当前温度试算只支持已登记的153㎡示范范围。它不是整个研究区的可改造面积。

### 2. 保存目标

在「本轮目标」填写以下讨论假设。已经有目标时，展开「调整预算与单价」。

| 输入 | 示例 |
| --- | --- |
| 预算 | 40000元 |
| 假设建设单价 | 300元/㎡ |
| 面积上限 | 留空 |

点击「保存预算与单价」。未点击保存的输入不会改变当前目标。费用不含养护，单价不是工程报价。

### 3. 生成空间候选

在「01 / 生成候选」填最低改造面积 `102`，点击「生成空间候选」或「按当前条件重新生成」。

在无额外保留区的示例中，系统检查6885个整数米单矩形，65个满足约束，整理出102㎡／30600元和128㎡／38400元两个代表候选。不同取向选中相同范围时会合并，不保证三个候选。

搜索检查登记范围、预算、面积上限、保留区与优先覆盖，不按降温、人体舒适或现场可施工性排名。无解会说明原因，不会自动减小最低面积。

### 4. 先评价，再判断

在「02 / 评价与比较」点击「评价本轮全部候选」。无需先采用。系统逐个运行当前候选，保留固定输入、模型与资料哈希、结果和运行依据；可用底部「停止本轮」取消，已完成结果保留。失败保留缺项，可手动重试。

比较表列出现状参考、两个候选的面积、新增费用、模型温差和情景预测温度。现状新增建设费为0，不包含既有费用或养护，也不表示现场无需改善。

**温差＝模型基线−情景预测，负数表示模型预测升温。** 示例模型基线约32.970℃，两个候选温差均约−0.058℃，未显示降温。扩大面积多投入7800元，模型结果几乎相同。因此本轮显示「未得到降温改善证据」，不能把扩大面积当作降温更优。

数值由真实运行产生，不自动填入未评价版本。模型、资料或基准不同的结果不直接选优。没有温差不确定性区间，小数值差异不能单独决定实际优劣。

### 5. 地图核对与保存方案

在「03 / 选择待复核方案」点「地图查看候选1／2」。工作台收起，地图完整显示登记区与选中范围，底部卡片给出候选名称、面积和费用。青绿是选中范围，黄色是登记区，粉色是保留区，蓝色是优先区。

核对后点「返回候选与评价」。如需保存供后续复核，可点击「采用候选」。采用会创建带来源的情景版本，并带入本轮相同输入下已经完成的有效评价，保留原运行依据，不重复推理。未提前评价的候选也可保存，温度保持待评价。

没有改善证据时，可以直接生成比较报告，记录本次未获改善的结果；不必为完成流程强行采用方案。

### 6. 报告与导出

点击「生成本轮比较报告」，或工作台底部「生成本轮报告」，随后点「下载比较报告」。报告包括现状参照、费用与温差比较、当前结论、版本和适用范围。

顶部「方案与成果」用于比较已经保存的两个版本，并下载规划进度包。若刚在工作台操作，先点成果面板的圆形刷新按钮。进度包增加候选评价记录和候选比较判断，连同会话、地图、版本与来源清单逐件记录哈希。

条件、候选或评价批次变化后，旧报告标为旧版，重新生成后再导出当前成果。目标、评价和情景写入账户；地图工程另外点击「保存场地」。

## 调整约束与地图编辑

展开「空间约束与自主绘制」，可在登记区内依次点矩形的两个对角。

| 操作 | 检查 |
| --- | --- |
| 保留范围 | 填写保留用途后保存。不得与改造范围重叠；更新后需重新生成候选。 |
| 优先区域 | 填写优先原因后保存。比较几何覆盖，不代表降温或人口受益。 |
| 改造范围 | 保存为新情景，再手动运行该版本评价。可直接选择整块登记区。 |

两个对角在东西和南北方向都需有间距。点错可取消重画。旧版和旧结果保留；恢复旧范围会按当前目标另建版本。

## 模型与资料的含义

本机使用原 V3 冻结模型和2022-09-28指定历史参考条件，没有重新训练。覆盖变化是假设不透水面转为树木／灌木覆盖；模型把面积转换为100米网格内的覆盖比例，同面积不同摆放暂不能区分。它不计算树荫、人体热舒适、实际受益人口或现场真实降温。

对话模型与温度模型分别连接。在齿轮中连接实际可用的 Qwen 等对话服务后，才可自由问答。未连接时可以继续使用规划表单。

热感知归档和现场核查位于 AI 规划助手。历史帖子是待核查线索，不等同温度观测；可人工补充核实位置、现场记录并关联场地。5312不执行新采集；日常工作台见[启动说明](工作台启动与验收.md)。

## 常见问题

| 情况 | 操作 |
| --- | --- |
| 5312打不开 | 双击「启动试用系统.cmd」，等待检查就绪。 |
| 采集页显示“此入口未启用新采集” | 5312按配置只提供历史归档和核查记录，重复检查不会开启新采集。可点“查看历史归档”；新采集在已连接浏览器的5181本机工作台运行，两个入口的账户和资料分别保存。 |
| 工作台入口不可用 | 先在规划流程载入成都示范区。 |
| 候选已过期 | 保存过的新预算、保留区或优先区改变了条件，重新生成。 |
| 评价失败／只完成部分 | 保留已完成记录，核对模型后手动重试，不会补零。 |
| 不知道哪个更好 | 先读本轮结论，再对照新增费用、模型效果与空间偏好；实际实施仍需现场复核。 |
| 已保存方案温度为空 | 展开该方案，手动评价；或先评价候选再采用。 |
| 报告是旧版 | 按当前条件和最新评价重新生成。 |
| 地图放得很大 | 当前试算区只有153㎡；按「返回候选与评价」继续工作台。 |

赛事的 CodeArts 开发、已有智能体／Skills 华为云服务操作及真实云部署分别验收，本地容器不能作为云部署证据，详见[交付说明](赛题1部署与交付.md)。

2026-11-26：5312仅更新了静态界面的采集状态说明，继续沿用原后台、账户数据卷和只读V3挂载；新采集保持关闭。禁用状态不再显示成“待处理”，不再循环检查，也不展示等待就绪的采集表单。此前的账户、工程和会话保留。

## 2026-11-24：评价适用性与真实数据参考案例

候选比较表后新增「这些结果能支持什么判断」。它检查本轮结果是否完整、基准与输入结构是否一致，并说明当前输出精度下能否区分模型温差。这里的“有差异”不代表实际干预效果有可靠差异，也不会自动推荐施工。

展开可查看模型限制和下一步核查事项。重新生成的报告及规划进度包包含同一套评价适用性说明；已有旧报告不会自动改写。
