# UrbanCool 当前系统 MVP 实际验收

检查日期为 2026-10-29（北京时间）。

## 结论

当前已经跑通网页、DeepSeek 对话、按需委派、目标登记、投入配置模板和讨论记录生成；尚未跑通“空间方案—情景编译—真实预测—评价比较—协同修改”的业务 MVP。

这不是仅由语言模型回答能力造成的问题。主计算能力存在缺口，地图工程与 Agent 会话尚未形成统一业务状态；本次还复现了任务先后顺序错误。

## 检查范围和方法

- 检查当前已运行的 5173 网页和 5181 Agent 服务，未重启或停止用户服务。
- 回读用户今天已有的两次本地对话，仅用于本地诊断，未将其发往模型服务。
- 浏览器进入公开工程样例 E4125_N33891，新建测试会话，使用此前已授权的公开样例摘要及演示预算/面积条件向官方 DeepSeek API 发送两轮问题。
- 对照前端、工具层、编排层、工程保存代码和《UrbanCool_AI_产品项目书_V2.0.md》。
- 本次没有修改业务源码，没有调用科研推理，没有启动微博采集，没有重跑全套构建测试。此前的软件测试通过不能代替本次业务验收。

## 实测一：生成配置并尝试预测

问题：

> 按讨论假设，预算10万元、候选面积800平方米、建设单价100元/平方米，保留建筑。生成并比较三档增绿配置，尝试预测温度。请明确能否给出具体增绿位置。

结果：

| 项目 | 实际结果 |
|---|---|
| 目标登记 | 100000 元、800 m²、100 元/m²，目标版本 1 |
| 三档配置 | 400 / 600 / 800 m²，假设建设费 40000 / 60000 / 80000 元 |
| 生成方法 | 按声明面积、预算和单价计算上限，再取 50% / 75% / 100%；没有执行布局搜索 |
| 空间对象 | 三个草案的 geometry 均为 null |
| 预测结果 | 三个草案的 predicted_delta_lst_c 均为 null，prediction_status 均为 not_run |
| 任务开销 | 13 次模型请求、16 次工具调用、3 次委派；累计输入 51695 tokens、输出 2305 tokens |
| 运行时间 | 第一轮根任务约 25.3 秒；单次样例结果，不是稳定性能基准 |

复现的顺序错误：

1. 主 Agent 登记目标。
2. 资料核查完成。
3. **方案尚未生成，先委派预测评估。**
4. 评估工具查询得到 no_current_options；随后把基线场景 ID 当作生成草案 ID，预测检查被 unknown_scenario 拒绝。
5. 主 Agent 才委派方案探索，生成三个有效配置草案。
6. 没有对新草案重新评估，直接生成讨论记录并总结。

因此，本轮并未完成“对生成草案执行预测接入检查”。模型服务确实未接通，但这个事实不能掩盖编排先后错误。系统提示中的建议顺序尚未成为后端强制依赖。

## 实测二：把方案显示到地图并编辑

问题：

> 把刚才的中等投入草案显示到地图上，让我能点选和修改它。

结果：2 次模型请求，读取项目能力及缺项后返回无法执行；没有新增地图对象，没有发生空间修改。工具清单中没有创建/更新方案几何的接口，AgentPanel 与地图仅连接了定位回调。

这里应区分“平台已有建筑、植被等来源几何”和“生成草案没有干预几何”。模型回复中概括性的“几何不存在”不能作为对所有 GIS 数据的事实判断。

## 问题归因

1. **数据连接不足。** 在新位置预览时，后台缺少对应指标与空间对象查询能力；缺项应清楚引导到受支持样例或资料登记，而不是反复输出长篇内部状态。
2. **计算链没有接通。** 温度预测、干预到特征转换、空间检查和候选搜索不能靠提示词或增加 Agent 补齐。
3. **编排缺少硬性前置条件。** 主 Agent 现在可自由选择委派顺序；应由程序校验有效方案 ID、版本和前置任务状态。
4. **业务状态分散。** 地图工程与会话目标、草案、运行结果没有共用完整方案对象。
5. **对话交付偏向解释。** 用户要求实际操作时，得到较多术语、缺项及开发移交事项，缺少可执行的下一步和明确操作结果。

## 建议的最小交付范围

先固定一个数据与模型支持条件明确的样例，不以全市任意位置作为首版验收范围。

1. 统一场地、基线、候选空间对象、方案 ID 和版本；明确区分已有来源几何、讨论候选和已核查空间。
2. 允许人工确认一至两个候选干预范围；Agent 草案写入同一方案对象，并在地图上预览、点选、修改。
3. 接通已验证温度推理包及其输入编译，只支持模型已有的干预口径；执行同条件下的基线与情景计算。
4. 用统一规则比较面积、假设费用和预测地表温度差，保留输入、模型、编码器与运行版本。
5. 修改预算或空间后，标记旧结果并重新计算；保存、重新打开后保持一致。

最小验收任务：选择受支持样例 → 声明目标和假设 → 形成可见的候选空间方案 → 检查并编译 → 明确启动真实预测 → 比较两案 → 修改后重算 → 保存并恢复。

科研模型移交是独立的交付依赖。模型未取得和验证前，可以完成地图方案与编排的工程闭环，但不能将其标为已完成温度预测的业务 MVP。02、03、04 的口径仍分别保留，不因本次整合默认联算。
