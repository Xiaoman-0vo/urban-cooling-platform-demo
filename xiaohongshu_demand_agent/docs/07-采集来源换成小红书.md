# 07 · 采集来源换成小红书（agent-reach 全链路接入）

> 状态：已接入并跑通端到端 demo。原微博采集器已删除，判定链 / 聚合 / 平台快照 / 聊天窗逻辑一行未改，只换了"数据从哪来"。

## 1. 为什么换

| | 微博（旧） | 小红书（新） |
|---|---|---|
| 登录态 | 需要从 Edge 里用 CDP 抠 Cookie（`.weibo-cookie`），过期就得重抠 | `agent-reach login xiaohongshu` 一次，登录态由 agent-reach 自己保管 |
| 接口 | `m.weibo.cn` 私有接口 + `weibo.com/ajax/...buildComments`，随时可能变 | agent-reach 的 `xiaohongshu` 渠道（search / read / comments），走 opencli 登录态浏览器桥 |
| 内容形态 | 140 字短文本 + 评论区 | 图文笔记正文 + 已加载的一级评论 |
| 本项目里的合规口径 | 只读公开内容 | 同样只读、不发布、不评论、不碰私密信息 |

**结论**：小红书更适合本项目——"笔记正文"天然比微博短文本更接近"一段完整的热体验描述"，评论里还能捞到具体的抱怨。

## 3. 采集器 `scripts/collect-xhs.mjs`

```bash
node scripts/collect-xhs.mjs --query "成都 遮阴" --limit 6 --comments 8 \
  --out data/raw_成都_xhs.json --job-id <id> --progress data/jobs/<id>.progress.json
```

三步，且**必须在同一轮里做完**：

1. `agent-reach xiaohongshu search "<城市> <关键词>"` → 拿到带 `xsec_token` 的签名链接；
2. `agent-reach xiaohongshu read "<签名链接>"` → 笔记正文（逐条）；
3. `agent-reach xiaohongshu comments "<签名链接>"` → 已加载的一级评论（逐条）。

约束（写在代码注释里，别改坏）：

- **签名链接不能缓存**：`xsec_token` 约 1 天后失效，所以 search 完立刻 read，落盘只存不含 token 的 `https://www.xiaohongshu.com/explore/<id>`。
- **单次 20–35 秒**：所以必须走后台任务 + 进度文件，不能同步等。
- **登录态失效**（`UPSTREAM_BROKEN` / 需要登录）→ 直接失败退出（exit 4），**不写残缺 raw 文件**，进度里带 `need_login: true`，聊天窗提示 `agent-reach login xiaohongshu`。
- **评论只取已加载部分**：`comments_loaded` + `comments_total_unknown: true`，如实标注，不承诺全量。

输出结构：沿用旧 schema `weibo_raw/1`（判定链按字段读，不认平台），差异只在：

```jsonc
"stats": { "channel": "xiaohongshu", "source_channel": "xiaohongshu_opencli", "mode": "live", ... },
"limits": [
  "登录态读取小红书公开笔记，非官方授权接口；仅只读，不发布、不评论、不采集私密信息。",
  "评论只包含页面已加载的部分（comments_loaded / total_unknown），不承诺全量导出。",
  "签名链接（xsec_token）会过期，本文件只保存不含 token 的 canonical 链接。"
]
```

## 6. 已知限制

1. **速度慢**：一条笔记 20–35 秒，4 条笔记 ≈ 2.5 分钟。要更多样本就得等，或用 `--limit` 控制（默认 6）。
2. **评论不全**：只拿页面已加载的部分，`total_unknown`。
3. **原始文件按城市覆盖**：`data/raw_<城市>_xhs.json` 同名会被下一轮覆盖（同一关键词复跑前先备份）。※（待补充：是否改成 `<城市>_<jobid>_xhs` 的命名，需确认）
4. **登录态会掉**：表现为 search 返回登录页或 `UPSTREAM_BROKEN`，重跑 `agent-reach login xiaohongshu`。
5. **笔记发布时间**：目前search/read 返回的字段里不一定有精确发布时间，缺失时 `published_at: null`，时间窗过滤按"缺则保留"处理。
